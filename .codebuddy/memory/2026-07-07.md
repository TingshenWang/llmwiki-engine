## reasoning 解耦：保存与流式显示分离
- 用户设计指令：reasoning **始终保存**到 artifact 日志（`.reasoning.md` + `provider_result.json`），`--reasoning` flag **仅控制流式显示**
- 测试维护策略：不加 `--reasoning` 跑测试 → 非流式 → 保持 DeepSeek prompt cache 命中率 → 测试完直接看日志中的 reasoning
- 用户体验策略：加 `--reasoning` → 流式实时显示思维链（牺牲缓存命中率换取可视化）

### 改动
- `providers.py` L223：`use_streaming = reasoning_callback is not None`（移除 `or spec.stream_reasoning`）
  - 流式现在**只**由 `reasoning_callback`（即 `--reasoning` flag）触发
  - `spec.stream_reasoning` 字段保留在 ProviderSpec 中（向后兼容），但不再影响 streaming 决策，标记为 deprecated
- `cli.py`：`--reasoning` help 文本更新为"实时流式显示模型思维链（会降低缓存命中率）。不加此选项时 reasoning 仍会保存到日志。"
- 新增测试 `test_stream_reasoning_spec_does_not_force_streaming`：验证 `spec.stream_reasoning=True` 时不传 callback 仍走非流式
- 全部 93 个测试通过

### 关键机制
- 非流式模式下，DeepSeek 在 response body 的 `choices[0].message.reasoning_content` 中返回思维链
- `_extract_reasoning_content(raw_response)` 从非流式响应体中提取 reasoning → 保存到 `ProviderCallResult.reasoning_content` → pipeline 写入 `.reasoning.md`
- 流式模式下，`stream_once` 从 SSE delta 中累积 `reasoning_content` → 同样保存
- 两条路径都保存 reasoning，区别仅在于是否实时显示
