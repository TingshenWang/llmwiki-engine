## LWM-051 根因分析 & 修复

### 根因
- `final_page_prompt`（初始生成 prompt）缺少"禁止 raw 路径"规则
- retry prompt（L555）和 repair prompt（L781）都有此规则，但初始 prompt 漏了
- 导致 `final_pages` 步骤生成的正文包含 `[来源：raw/009-xxx.md]` 等内联路径引用
- `final_coverage_repair` 步骤发现后删除这些路径，把 1 次格式修复记为 N 个 claim 的 `updated_content`

### 修复
- `prompts.py` `final_page_prompt` instructions 中加入：
  "正文中不得包含 raw、sources、logs、index、Source_* 或 source page 的 wikilink、Markdown link、HTML href；来源归因通过 source_refs 字段完成，不要在正文中内联标注来源文件路径。"
- `pipeline.py` 新增 `_strip_raw_path_references` 函数 + `_RAW_PATH_PATTERN` 正则
  - 匹配 `[来源：raw/xxx.md]`、`[raw/xxx]`、`[text](raw/xxx)`、裸 `raw/xxx.md` 等模式
- `_sanitize_section_body_markdown` 中调用 `_strip_raw_path_references`（清理渲染 markdown）
- `_normalize_final_pages` 中清理每个 section 的 `body_markdown`（确保传给 repair 步骤的数据也干净）
- 5 个新测试：4 个单元测试 + 1 个集成测试
- 98 个测试全部通过

## wikilink 数量限制插件化
- 之前：`BODY_WIKILINK_LIMIT = 2` 硬编码在 related.py + prompt 中写死 "0-2 条"
- 现在：`PagePlugin.body_wikilink_limit` 字段控制（默认 2，向后兼容）
- 改动文件：
  - `page_plugin.py`: PagePlugin 加 `body_wikilink_limit: int = Field(default=2, ge=0)` + DEFAULT_PAGE_PLUGIN 加 `"body_wikilink_limit": 2` + `page_plugin_writing_card` 输出 limit
  - `related.py`: `final_markdown_link_issues` 和 `precanonical_link_errors` 加 `body_wikilink_limit` 参数（默认 BODY_WIKILINK_LIMIT 保持向后兼容）
  - `prompts.py`: 三个 prompt 中的 "0-2 条" / "最多 2 条" 改为 f-string 从 `page_plugin.body_wikilink_limit` 读取
  - `pipeline.py`: `_canonical_final_markdown` 加 `body_wikilink_limit` 参数，`_normalize_final_pages` 从 `page_plugin` 读取并传入
- 2 个新测试：`test_body_wikilink_limit_from_plugin`（验证 limit=5 时 5 条不报错、6 条报错）+ `test_default_plugin_body_wikilink_limit_is_2`
